# 地标传媒 · 广告销售线索公海管理系统 — 产品需求文档（PRD）

版本：v1.0 ｜ 适用：地标传媒户外大屏广告销售团队 ｜ 形态：H5（手机）+ Web 管理端（同一套前端，按角色/屏宽自适应）+ 微信小程序壳

## 1. 目标

建立“**公海池 → 认领进入个人私池 → 超时未有效跟进自动回流公海 → 他人再次认领**”的线索闭环，做到：

1. 线索不压单：认领后 30 天（可配）没有有效更新就自动回流；
2. 不撞单：同一条线索同一时间只属于一个人，同名公司不可重复录入；
3. 不泄密：销售之间私池完全隔离，普通销售无导出权限；
4. 可追溯：认领、退回、回流、修改、跟进、强制回收全部留痕，日志与跟进记录不可删除；
5. 好录入：手机端口述，AI 自动拆分到字段。

## 2. 角色与权限

| 能力 | 普通销售 | 销售总监 | 超级管理员 |
|---|---|---|---|
| 浏览公海可认领线索 | ✅（电话/微信默认脱敏） | ✅ 明文 | ✅ 明文 |
| 认领 / 个人池 / 编辑 / 跟进 / 退回 | ✅ 仅自己名下 | ✅ 仅自己名下 | ✅ 仅自己名下 |
| 查看他人私池线索、联系方式、跟进记录 | ❌（接口直接 403） | ✅ | ✅ |

| 总监看板 / 到期预警 / 流转台账 | ❌ | ✅ | ✅ |
| 强制回收任意销售线索 | ❌ | ✅ | ✅ |
| 批量导入 | ❌ | ✅ | ✅ |
| 导出报表 | ❌ | ✅（每次导出写日志） | ✅ |
| 录入新线索 | ✅（可由开关关闭） | ✅ | ✅ |
| 账号 / 角色 / 密码重置 | ❌ | ❌ | ✅ |

- 管理员停用某个销售账号时，其名下线索自动全部回收公海（销售离职场景），并写日志。

## 3. 核心概念

### 3.1 线索状态

| 状态 | 含义 | 出现在 |
|---|---|---|
| `pool` 公海待认领 | 无归属人 | 公海可认领列表、台账 |
| `owned` 已认领 | 有且仅有一个归属人 | 归属人的个人池、台账（标记：已认领｜认领人｜认领时间） |

线索记录**永不删除**（数据库触发器强制），认领后只是从“可认领视图”隐藏。

### 3.2 有效更新（重置回流倒计时）

以下任一动作即为有效更新，回流到期时间重置为“当前时间 + 回流周期”：

1. 修改/补充客户信息（任一字段**实际发生变化**；点保存但内容没变不算）；
2. 新增一条跟进记录；
3. 更新跟进阶段。

### 3.3 回流（三种来源）

| 类型 | 触发 | 是否需要备注 |
|---|---|---|
| 主动退回 `release` | 归属人手动退回 | 必填退回原因 |
| 超时自动回流 `auto_recycle` | 系统每 10 分钟扫描，`到期时间 ≤ 当前时间` | 系统自动写明上次有效更新时间 |
| 强制回收 `force_recycle` | 总监/管理员操作；或账号停用 | 选填 |

回流后：清除归属人和计时字段；记录“上一任认领人 / 回流方式 / 回流时间”；公海中显示“曾被 XX 认领过”；**历史跟进、认领历史、日志全部保留并永久跟随线索**。下一位认领人默认可查看历史跟进（可由开关关闭）。

## 4. 业务流程

### 流程 1 新增线索进公海
- 总监/管理员：单条录入，或下载 CSV 模板批量导入（同名公司自动跳过，行业不存在的行报错，最多 5000 行/次，GBK/UTF-8 自动识别）。
- 销售：前端录入（可勾选“录入后直接认领”），录入前自动查重：已在公海→提示直接认领；已被他人跟进→提示“已被其他销售跟进中”（不暴露是谁、不暴露联系方式）。

### 流程 2 认领
1. 公海列表按行业 / 意向等级 / 跟进阶段 / 新线索·回流线索 / 关键词筛选；
2. 点击“认领” → 二次确认（提示回流规则）；
3. 服务端用**条件更新**（`WHERE status='pool'`）原子转移归属，并发认领只有一人成功，其余返回“手慢了”；
4. 写入认领历史、操作日志，回流倒计时启动；
5. 可选：个人池上限（默认不限）。

### 流程 3 跟进与维护
- 个人池默认按“到期时间最近”排序，剩余 ≤ 预警天数高亮橙色，≤1 天红色；
- 详情页：表单编辑、语音录入、新增跟进（内容 / 更新阶段 / 下次跟进时间）、退回公海；
- 弱网/离线：列表和详情读缓存；离线提交的跟进暂存本地，联网后自动补交。

### 流程 4 自动回流
- 定时任务每 `RECYCLE_SCAN_MINUTES`（默认 10）分钟执行；服务启动时立即执行一次；
- 管理员可在“系统设置”中手动触发一次扫描；
- 修改回流周期后，所有私池线索的到期时间按“上次有效更新 + 新周期”重新计算。

### 流程 5 总监管理
- 看板：公海存量、私池数、即将回流、本周新增、已成交；本周流转（认领/退回/超时回流/强制回收/跟进）；各销售明细（持有、本周认领、本周退回、即将回流、累计被回收、已成交、本周/近 30 天跟进次数）；行业分布；
- 到期预警清单 + 一键强制回收；
- 流转台账：认领→回流→再认领全链路，可按动作筛选；
- 全员线索台账：按销售/状态/行业/阶段筛选，进入任意线索看全部跟进与日志；
- 导出：公海存量、私池线索、即将回流、已回流、成交、全部台账、销售统计（CSV，Excel 直接打开）。

### 流程 6 权限隔离（强制）
- 所有权限判断在服务端完成（`server/src/leads.js` 的 `assertCanView` / `assertOwner` 等），前端隐藏按钮只是体验；
- 销售请求他人私池线索：返回 403，响应体不含任何客户信息；
- 公海中对销售脱敏电话/微信（开关可关），认领后可见完整信息。

## 6. AI 语音录入

1. 手机上点 🎤 口述（支持浏览器语音识别的环境实时转文字）；不支持的环境（如微信内置浏览器）提示使用**输入法自带的语音输入**，同样转成文字；
2. 点“AI 识别填充”：
   - 配置了 `ANTHROPIC_API_KEY`：调用 Claude 做语义抽取（结构化 JSON 输出，枚举字段只能从系统选项中选，没说到的字段留空，不编造）；
   - 未配置 / 调用失败：自动降级为本地规则引擎（手机号、微信号、公司名、对接人、部门、岗位、地址、行业关键词、意向、阶段、来源、“明天/下周三/5月20日”等相对日期）；
3. 识别结果逐项勾选后“填入表单”，高亮显示，**销售确认点保存才写库**（保存即有效更新）；
4. 识别不到必填项时提示手动补充；口述中的沟通过程同时生成一条“跟进记录”草稿。

## 7. 日志留痕

动作：录入、导入、认领、主动退回、超时回流、强制回收、修改信息（记录每个字段的旧值→新值）、更新阶段、新增跟进、语音识别、导出、修改配置、账号新增/修改/重置密码。

日志表、跟进表通过 SQLite 触发器禁止 UPDATE/DELETE；线索表、认领历史表禁止 DELETE——任何角色（包括直接操作数据库的程序）都无法删除。

## 8. 系统配置（超级管理员）

- 自动回流周期（1–365 天，默认 30）、到期预警天数（默认 7）、个人池上限（默认不限）；
- 行业标签、跟进阶段、意向等级、线索来源：增删改、停用；被使用过的选项删除时自动改为“停用”，改名同步到已有线索；
- 账号：新增、改角色、停用/启用（停用自动回收线索并让其登录失效）、重置密码；
- 权限开关：公海脱敏、继承历史跟进、销售可录入线索。

## 9. 非功能

- 安全：bcrypt 密码；JWT 7 天，修改/重置密码或停用账号立即令旧令牌失效；登录失败 10 次锁 10 分钟；CSV 导出防公式注入；敏感数据只在服务端按权限下发。
- 可用性：手机优先，iPhone 刘海屏安全区适配；≥960px 自动切换为侧边栏管理端布局。
- 离线：应用外壳 Service Worker 缓存；列表/详情 localStorage 缓存；离线跟进队列。
- 数据：单文件 SQLite，每次写事务原子落盘，每日自动备份保留 30 份。
- 扩展：成交单、广告排期、业绩统计可在 `leads` 基础上新增表；数据量大或多实例部署时迁移到 MySQL/PostgreSQL（SQL 均为标准写法）。

## 10. 禁止项落实

| 禁止项 | 落实方式 |
|---|---|
| 一条线索同时被多人认领 | 条件更新原子认领 + 表级 CHECK（pool 必无归属人、owned 必有归属人）；有并发认领测试 |
| 普通销售查看同事私池 | 服务端 403；列表查询强制 `owner_id = 当前用户`；有测试 |
| 自动回流清除历史跟进 | 回流只改线索归属字段；跟进表禁止删除/修改（触发器）；有测试 |
| 认领后台账删除线索 | 线索表禁止删除（触发器），认领只改状态；有测试 |
